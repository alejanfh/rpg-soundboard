# RPG Soundboard

A static Next.js soundboard for a game master running *Trail of Cthulhu* (El Rastro de Cthulhu). The GM picks an adventure, moves scene by scene, and the app crossfades the scene's music and ambience while offering one-tap sound effects and a short per-scene cue sheet. Single user, no backend, no accounts. The UI and content are in Spanish; the code is in English. The iPad is the primary device.

## Quick start

```bash
npm install
npm run dev     # dev server at http://localhost:3000
npm test        # Vitest, includes the content integrity gate
npm run lint    # ESLint
npm run build   # static export to out/
npm run audio   # build audio files from scripts/audio-sources.json
```

Note: this repo uses a Next.js version with breaking changes. Read the relevant guide in `node_modules/next/dist/docs/` before changing framework code.

## Project structure

Folders are named after what they do.

| Path | Purpose |
|---|---|
| `src/audio-engine/` | Custom Web Audio engine: music/ambience tracks with crossfade, one-shot SFX, per-layer volume, silence-all. No audio library. |
| `src/sound-library/` | The global sound library: `sounds.ts` (all `Sound` entries with credits), types, id-to-path helpers, search. |
| `src/adventures/` | One file per adventure (scenes, music/ambience/SFX ids, cues). `index.ts` registers them. Adventures reference sound ids only. |
| `src/soundboard/` | The play UI: scene list and panel, mixer, transport bar, library drawer, unlock overlay, cue firing. |
| `src/content-integrity/` | Tests that validate library and adventures (broken ids, wrong kinds, missing files, missing credits). |
| `src/app/` | Next.js routes: `/` (adventure list), `/partidas/[id]` (play), `/creditos` (generated attribution page). |
| `scripts/` | `audio-sources.json` (source manifest) and `build-audio.mjs` (download, trim, normalize, encode). |
| `public/audio/{music,ambience,sfx}/` | The generated MP3 files. |
| `docs/superpowers/specs/` | Design spec. |

## How to add content

1. **Add the source** to `scripts/audio-sources.json` (id, kind, origin, license and credit metadata, URL, trim window). Header of `scripts/build-audio.mjs` documents every field.
2. **Build the audio:** `npm run audio`. Output goes to `public/audio/<kind>/<id>.mp3`, loudness-normalized and encoded at 128 kbps. Downloads are cached in `scripts/.cache` (git-ignored). Flags:
   - `npm run audio -- --force` rebuild everything
   - `npm run audio -- --only a,b` build only the listed ids
   - `npm run audio -- --kind sfx` build only one kind (`music`, `ambience`, `sfx`)
3. **Add a `Sound` entry** in `src/sound-library/sounds.ts` with the same id, a Spanish title and tags, and the credit (author, source, license, URL, `workTitle` for CC-BY). Credit metadata is mirrored from the manifest.
4. **Add or modify an adventure** in `src/adventures/` and register it in `src/adventures/index.ts`.
5. **Run `npm test`.** The integrity gate fails on unknown sound ids, wrong kinds (`musicId` must be music, `ambienceId` ambience, `sfxIds` sfx), duplicate ids, missing files under `public/`, or missing/invalid credits.
6. **Deploy** (see below).

### Content constraints

- **Sizes:** SFX under 300 KB; music and ambience loops 2 to 5 minutes (the build script trims and repeats toward that range).
- **Ids:** kebab-case, unique and stable. Adventure ids become URLs (`/partidas/<id>`), so they must be URL-safe. Sound ids also name the file: `src` must equal `/audio/<kind>/<id>.mp3` (the integrity gate checks it).
- **CC-BY needs `workTitle`:** every CC-BY-4.0 sound must carry the original work's title in its credit, or the integrity gate fails. `/creditos` adds the "edited" notice CC-BY requires.
- **Manifest and library must agree:** `scripts/audio-sources.json` and `src/sound-library/sounds.ts` are checked against each other (ids, kind, author, license, source page URL, work title).

## Audio licensing policy

- Allowed licenses: CC0, CC-BY 4.0 (credited), US public domain, and sounds generated by our scripts.
- Sources: Freesound (CC0 only, verified per sound page), Incompetech / Kevin MacLeod (CC-BY 4.0), OpenGameArt (CC0 only), Internet Archive recordings published 1925 or earlier, generated drones.
- Excluded: Pixabay, BBC RemArc, Tabletop Audio, Sonniss (license incompatible with public redistribution or unverifiable).
- No recordings from 1926 onwards (not US public domain).
- `/creditos` is generated from the sound library, so every sound's credit must be in `sounds.ts`; no separate credits file to maintain.

## Known limits

- **iPad:** audio only starts after the "Toca para activar el sonido" tap, and the hardware silent switch must be off.
- The app must stay in the foreground; background tabs may suspend audio.
- Online only: no offline mode or PWA caching.
- Public site, no password.

## Real-device smoke checklist

Run this on the iPad (or phone) before a session; automated tests cannot cover real audio hardware.

1. Open an adventure: the unlock overlay shows. Tap it: it disappears and the screen stays awake.
2. With the hardware silent switch on, no sound is heard; switch it off and sound plays.
3. Pick a scene: music and ambience fade in. Pick another scene: both crossfade (about 3 s, no gap or click).
4. Fire a cue and several SFX: they play over the music, overlapping when pressed repeatedly.
5. SILENCIO fades everything out; "Reanudar" brings it back, including any track the OS had paused.
6. Mid-scene, take a phone call or switch app, then come back: tap the unlock overlay if it shows and confirm music and ambience resume (re-tapping the scene also revives them).
7. Library: open "Biblioteca", search by title or tag (accent- and case-insensitive), play an SFX and swap a music or ambience track without changing the scene.
8. `/creditos` lists every sound with author, license and source links.

## Deployment

Hosted on Vercel as a fully static site (`output: 'export'` in `next.config.ts`; `npm run build` writes `out/`). No environment variables or server runtime are needed. The owner deploys manually; nothing in this repo pushes or deploys on its own.

1. **Git integration (recommended):** push the repo to a Git provider and import it in Vercel. Every push to the production branch deploys.
2. **CLI:** run `vercel` (preview) or `vercel --prod` from the repo root. `.vercelignore` excludes `out/`, `node_modules/`, `.next/`, `scripts/.cache/`, `.superpowers/` and `*.tsbuildinfo` so the upload stays well under Vercel Hobby's 100 MB limit.
3. **Settings:** keep the **Next.js** framework preset; it serves the static export from `out/` without further configuration.
4. **Install command (optional):** `ffmpeg-static` downloads a binary during install. The audio pipeline (`npm run audio`) is dev-only and the committed MP3s are what ship, so on Vercel you can set the install command to `npm ci --ignore-scripts` to skip that download.
